# OctoAcme Project Management Docs

Welcome to the OctoAcme Project Management documentation. This directory contains comprehensive guides for managing projects from initiation through retrospective.

## Quick Overview

OctoAcme follows a structured, lifecycle-based approach to project management that emphasizes customer value, iterative delivery, and clear ownership. The process spans five key phases: **Initiation** (validating business need and stakeholder alignment), **Planning** (breaking work into shippable increments with defined acceptance criteria), **Execution** (day-to-day delivery with daily standups and regular reviews), **Release** (standardized deployment with pre-release checks and rollback plans), and **Close & Retrospective** (capturing learnings and improvements).

The organization operates with clearly defined roles and responsibilities across three primary personas: **Project Managers** (coordinating delivery and managing stakeholder communications), **Product Managers** (owning the vision and measuring outcomes), and **Developers** (implementing features collaboratively and identifying technical risks). This structure creates clear accountability while maintaining cross-functional collaboration through regular touchpoints, including daily standups, weekly PM-to-PdM syncs, and monthly stakeholder updates.

Quality and execution rigor are central to OctoAcme's delivery model. The team enforces a **Definition of Done** that includes small PRs (≤400 lines), automated CI with tests and linting, at least one approval before merge, and security scanning. Execution is tracked through velocity and burndown metrics, with regular demos and reviews scheduled to validate progress. Finally, OctoAcme embeds **continuous improvement** into its culture through regular retrospectives after sprints, releases, or milestones, with action items tracked in the project backlog and reviewed in weekly syncs.

## Core Principles

- **Customer-first**: prioritize customer value and usability
- **Iterative delivery**: deliver small, testable increments
- **Clear ownership**: named Project Manager (PM) and Product Lead per project
- **Data-informed decisions**: measure impact and iterate based on evidence
- **Psychological safety**: encourage feedback and learning

## Project Lifecycle

### 1. [Initiation](./octoacme-project-initiation.md)
Validate business need, align stakeholders, create Project One-pager, make go/no-go decision.

### 2. [Planning](./octoacme-project-planning.md)
Break work into shippable increments, identify dependencies, define Definition of Done, create release plan.

### 3. [Execution & Tracking](./octoacme-execution-and-tracking.md)
Manage day-to-day delivery, maintain project board, run standups and demos, escalate blockers.

### 4. [Release & Deployment](./octoacme-release-and-deployment.md)
Prepare release notes, deploy to production, run smoke tests, manage rollback if needed.

### 5. [Retrospective & Continuous Improvement](./octoacme-retrospective-and-continuous-improvement.md)
Capture learnings, identify improvements, track action items, celebrate successes.
